# CodelyDev — Project History

A running record of how the site was built and why it looks the way it does.
Newest phases last. Keep this file updated whenever a significant phase lands.

---

## Phase 1 — Scaffold

- Next.js **16.2.9** (App Router, Turbopack), React **19.2.4**, Tailwind CSS **v4**.
- Fonts: Geist + Geist Mono (UI/code) and **Poppins** (display/headings, `.display` class).
- Note: Next 16 has breaking changes vs older versions (`params` is a `Promise`,
  `generateMetadata` / `generateStaticParams` conventions). Docs live in
  `node_modules/next/dist/docs/` — read them before touching routing code.
- Baseline pages: `/`, `/about`, `/not-found`, plus starter assets.

## Phase 2 — Brand alignment

- Brand colors sampled directly from `codelydev logo.png`:
  | Token | Value | Use |
  |---|---|---|
  | Navy | `#071B2E` | Backgrounds, dark text on light UI |
  | Cyan | `#0CC0DF` | Primary brand accent |
  | Teal | `#00C4CC` | Gradient end |
- Design tokens live in `src/app/globals.css` (`@theme inline`), including
  `.display`, `.gradient-text`, `.brand-gradient`, `.btn-primary`, `.btn-ghost`,
  `.pill`, `.input`, `.card`, `.prose`.
- **Contrast decision:** light theme uses a darkened brand (`--brand: #007a93`,
  gradient `#007a93 → #00998c`) to stay WCAG-AA on white; dark theme uses the
  pure `#0cc0df → #00c4cc`.
- Dark mode is the default. An inline `<script>` in `layout.tsx` `<head>`
  (no-flash `themeScript`) applies the `.dark` class before first paint; the
  preference is stored in `localStorage.theme`.
- Header/footer lockups, favicon and social images were first generated as
  hand-drawn approximations of the logo (strokes + Poppins text).

## Phase 3 — Content layer (blog-ready)

- Markdown posts in `content/posts/*.md` with YAML-ish frontmatter
  (`title`, `description`, `date`, `tags`, `cover`, `author`, `featured`).
- Parsers/utilities: `src/lib/markdown.ts` (hand-written frontmatter parser),
  `src/lib/posts.ts` (lookup, related posts, tag counts).
- Markdown rendered with `marked@18.1.0` + `dangerouslySetInnerHTML` inside the
  `.prose` styles (no runtime MDX).
- Routes: `/blog`, `/blog/[slug]`, `/blog/tag/[tag]` (12 tags), `rss.xml`,
  `sitemap.xml`, `robots.ts`, `opengraph-image.tsx`.
- Metadata fix: `blog/[slug]` and `shop/[slug]` `generateMetadata` now take
  `parent: ResolvingMetadata` and pass `images: previousImages` so every page
  emits a correct `og:image`.
- 5 seed posts: server-components-data-model, pragmatic-state-management,
  core-web-vitals-fix-list, typescript-patterns-that-catch-bugs,
  digital-products-checkout-design.

## Phase 4 — Digital products & checkout

- Catalogue: `src/lib/products.ts` — **6 SKUs** (4 eBooks/PDFs, 1 cheatsheet
  pack, 1 bundle) with `cover`, `price`, `currency`, `type`, `pages`, `format`.
- Cart: `src/lib/cart-store.ts` + `CartProvider` — module-level store read with
  `useSyncExternalStore` (the lint rule `react-hooks/set-state-in-effect`
  forbids `useState` in effects, so all persisted state uses this pattern).
  Same pattern for `src/lib/orders.ts` and theme.
- Routes: `/shop`, `/shop/[slug]`, `/cart`, `/checkout`, `/order/[id]`.
- Checkout flow: `CheckoutForm` → `POST /api/checkout` → order id →
  `/order/[id]` with download links.
- **`src/app/api/checkout/route.ts` resolves prices and file paths
  server-side** (never trusts client prices) and currently runs in **demo
  mode** — there is a marked integration point for Stripe.
- Deliverables: placeholder PDFs generated by `scripts/make-pdfs.mjs` into
  `public/downloads/*.pdf` (regenerate with `node scripts/make-pdfs.mjs`).
- Orders persist in `localStorage` (demo) so a reload keeps the receipt.

## Phase 6 — Canonical vector logo (2026-10-08)

- **Source of truth:** `public/Codelydev_logo.svg` (the vectorized reference
  supplied with the project — 2000×2000, navy `#071B2E` background, cyan
  `#0CC0DF` path, white `#FFFFFF` path, `M/L/Z` geometry only).
- New pipeline: **`npm run logo`** → `scripts/build-logo.mjs`:
  1. Parses the two reference paths and splits them into subpaths.
  2. Classifies subpaths by bounding box: everything above `y=1200` is the
     `{ / }` mark (2 cyan braces + 1 white slash); everything below is the
     wordmark (7 cyan + 7 white subpaths, incl. letter counters).
  3. Regenerates every asset and the shared path data:
     | Output | Purpose |
     |---|---|
     | `public/codelydev_mark.svg` | Mark only, transparent |
     | `public/codelydev_icon.svg`, `public/favicon.svg` | Mark on navy rounded square |
     | `public/codelydev_dark.svg` | Full stacked logo (identical to reference); JSON-LD `logo` URL |
     | `public/codelydev_light.svg` | Light theme: white page, navy letters, `#007A93` cyan |
     | `public/codelydev_lockup(_light).svg` | Horizontal lockup, transparent |
     | `src/lib/logo-paths.ts` | AUTO-GENERATED path data + lockup transforms for React |
- `src/components/Brand.tsx` now renders the **real vector paths** instead of
  hand-drawn strokes/text: `LogoMark` (theme fills `var(--brand)` /
  `var(--foreground)`) and `Wordmark` (horizontal lockup, viewBox
  `0 0 1600.707 238`).
- Wired everywhere:
  - Navbar lockup (h-7/h-8), footer lockup (h-9)
  - Blog/product cover watermark (real mark at 16% opacity)
  - Empty cart + order-not-found icons
  - `opengraph-image.tsx` — full lockup drawn with satori SVG paths
  - `favicon.svg`, JSON-LD `logo` (`/codelydev_dark.svg`), new
    `apple-touch-icon.png` (`icons.apple` in metadata)
- PNG renders regenerated from the SVGs via a headless-Chromium one-off:
  `codelydev_dark.png`, `codelydev_light.png` (512×512), `apple-touch-icon.png`
  (180×180).
- Verification: **25/25 logo checks** (`verify-logo.js`) incl. pixel-sampling
  the OG image (navy background, cyan/white geometry present, letter counters
  *not* filled → `fill-rule` works in satori) and computed CSS fills in both
  themes; **22/22 E2E** still green; lint + build clean.

## Phase 7 — Supabase admin blogging (2026-10-08)

Admins can now sign in and publish posts; Supabase is the source of truth for
published posts with a safe file-based fallback.

- **Stack:** `@supabase/supabase-js@2` + `@supabase/ssr@0.12`. Env (in
  `.env.local`, documented in `.env.example`): `NEXT_PUBLIC_SUPABASE_URL`,
  `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`.
- **SSR helpers** (project-local copies of the Supabase snippets):
  `src/utils/supabase/{server,client,middleware}.ts`.
- **`src/proxy.ts`** — Next 16 renamed `middleware.ts` → `proxy.ts`; the proxy
  refreshes the auth session (`supabase.auth.getUser()`) and optimistically
  guards `/admin/*`: unauthenticated → `/admin/login?next=…`, signed-in users
  are bounced off the login page. Real authorization (admin membership) is
  enforced in the layout + server actions + RLS, never in the proxy alone.
- **Database** — `supabase/migrations/0001_posts.sql`:
  - `posts` table (slug unique, markdown `content`, `tags text[]`, cover,
    featured, published, date, `updated_at` trigger) + GIN index on tags.
  - `admins` membership table + `public.is_admin()` security-definer helper.
  - RLS: anon/authenticated read **published rows only** (admins also see
    drafts); only admins may insert/update/delete.
  - Setup flow documented in the file header (create user → insert into
    `admins` → run seed).
- **Seeding** — `node scripts/seed-sql.mjs` regenerates `supabase/seed.sql`
  from `content/posts/*.md` (dollar-quoted bodies, `on conflict do nothing`),
  so the SQL editor can import the 5 starter posts with no service-role key.
- **Data layer** — `src/lib/posts.ts` is now async:
  - `getAllPosts()` = `unstable_cache(loadPosts, ["all-posts"], { tags:
    ["posts"], revalidate: 3600 })`, DB-first via an unauthenticated Supabase
    client (no `cookies()`, so static generation still works).
  - **Fallback:** no env / query error / empty table → local markdown files
    (keeps builds and starter content working before the DB is seeded).
  - All callers updated to `await` (home, `/blog`, tag pages,
    `generateStaticParams`, RSS, sitemap).
- **Admin UI** (`src/app/admin/`, noindex via layout metadata + `robots.ts`
  `Disallow: /admin`):
  - `/admin/login` — server page + client `LoginForm`
    (`signInWithPassword`), `next` redirect param is sanitised.
  - `(protected)/layout.tsx` — server `getUser()` guard, membership check
    (signed-in non-admins get a "no access" panel, never a redirect loop),
    admin header with Dashboard / New post / View site / Sign out.
  - `/admin` — dashboard: status pills (Published/Draft), edit + delete
    (client confirm), empty state.
  - `/admin/posts/new` + `/admin/posts/[id]` — `PostEditor` (client): live
    markdown preview (reuses `marked` via `renderMarkdown`), auto-slug
    (`slugify` in `src/lib/slug.ts`, unique-checked server-side → 23505 →
    friendly error), cover picker, tags, featured, excerpt, date, author.
  - `src/app/admin/actions.ts` — server actions `createPost`, `updatePost`,
    `deletePost`, `signOut`, all re-checking auth + membership. Publish state
    is driven by submitter `intent` buttons (React 19 includes the clicked
    button's name/value in FormData).
  - **Revalidation:** `updateTag("posts")` (read-your-own-writes on the data
    cache) + `revalidatePath` for `/`, `/blog`, `/blog/[slug]`,
    `/blog/tag/[tag]`, `/rss.xml`, `/sitemap.xml` and the admin routes —
    publishing is visible immediately.
- **Verification so far:** lint + `tsc` + build green (41 routes, `ƒ Proxy`
  registered); regression **22/22 E2E** + **25/25 logo checks** still pass;
  admin Part A **7/7** (unauth redirects incl. `next` param, login renders,
  wrong-password error round-trips to Supabase). Full login → publish →
  `/blog` → cleanup flow (`verify-admin.js` Part B) is ready and runs once the
  SQL migration/seed is applied and admin credentials are supplied.

## Phase 8 — Image management with IDrive e2 (2026-10-08)

Full post/update/delete image workflow for the blog, backed by IDrive e2
(S3-compatible object storage).

- **Storage:** IDrive e2 bucket `codelydev` (region `eu-central-1`), env
  `IDRIVE_E2_*` (placeholders in `.env.example`, real keys only in
  `.env.local` — never committed). `@aws-sdk/client-s3` +
  `@aws-sdk/s3-request-presigner`.
- **Key finding (why the design looks like this):** IDrive e2 **ignores
  `ACL: public-read`** (object ACLs stay `FULL_CONTROL`) and the API key
  **cannot `PutBucketPolicy` (AccessDenied)** — anonymous GETs are 302'd to
  idrivee2.com. Presigned URLs work perfectly. → **Bucket stays private.**
- **Serving:** `src/app/api/media/[...key]/route.ts` validates the key
  (`posts/` prefix, no traversal), `HeadObject`s to 404 missing objects, then
  **302s to a 10-minute signed GET URL** with `Cache-Control: max-age=600`.
  Image bytes travel directly from IDrive to the browser; Next only issues
  the redirect.
- **Uploads:** browser → server action `createMediaUpload`
  (`admin/media-actions.ts`, admin-gated) → presigned **PUT** → browser
  uploads the file **straight to IDrive** (no Next body-size limit). Shared
  client helper `src/lib/media-upload.ts` (types whitelist: PNG/JPEG/WebP/
  GIF/AVIF, 8 MB cap, no SVG). `src/lib/media-url.ts` is the SDK-free
  URL helper so client components never bundle the AWS SDK.
- **Editor (`PostEditor`):**
  - **Cover image** card: upload/replace/remove, preview, persisted via
    hidden `cover_image` field → new `posts.cover_image` column
    (`supabase/migrations/0002_cover_image.sql` — run after 0001).
  - **Inline images:** "＋ Image" button inserts `![alt](url)` at the cursor;
    **paste-to-upload** supported on the textarea.
- **Rendering:** `Post.coverImage` threaded through `posts.ts` (DB select +
  file fallback `null`); `CoverArt` takes an optional `image` prop and renders
  `next/image` (fill/`object-cover`) instead of the gradient+watermark;
  wired into `PostCard` and `blog/[slug]`.
- **Media library:** `/admin/media` (nav "Media" link) — upload card, grid of
  thumbnails with size/date, **Copy URL** (clipboard) and **Delete**
  (confirm → `removeMedia` → `router.refresh()`).
- **Verification: `verify-media.js` 10/10** (302 → signed URL → bytes match,
  bucket private, non-`posts/` keys, traversal and missing objects 404,
  `/admin/media` gated); regression **22/22** + **25/25** logo + admin Part A
  **7/7** all still green; lint/tsc/build clean (44 routes).
